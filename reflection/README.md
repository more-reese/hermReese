# Reflection

Using Hermes to think about product — including Hermes itself. This is where I use the agent as a thinking partner for the PM work: where it succeeds, where it breaks, what I'd build, and how I'd measure whether it's getting more useful.

This isn't separate from the rest of the repo. It's the feedback loop — the part where the artifacts and the surface get examined, and what I learn feeds back into the next session. Philosophy → surface → artifacts → **reflection** → philosophy.

## Contents

- **[friction-log.md](friction-log.md)** — Real friction points I've hit using Hermes, with specifics. The honest version — where the product breaks for me.
- **[roadmap-ideas.md](roadmap-ideas.md)** — If I owned the Hermes Agent roadmap, here's what I'd prioritize and why. Grounded in real usage.
- **[onboarding-analysis.md](onboarding-analysis.md)** — The user journey from install to first useful task to sustained use. I went through it myself.
- **[metrics.md](metrics.md)** — How I'd measure whether Hermes is becoming more useful. Activation, repeat use, task completion, trust growth.
- **[evals/](evals/)** — Real evaluations with acceptance criteria and measured results. Does the agent actually complete tasks?

## What this shows

The "use Hermes daily, understand where it succeeds and breaks down, and turn that into product decisions" requirement, shown in practice. Each file is produced through a Hermes session — the agent is the thinking partner, not just the subject.

The friction log is the most important file. A portfolio that only shows successes isn't a portfolio — it's a press release. The friction is where the product work lives.
